# ポート技術面接：NLP学習中心の発表 想定Q&A
2026年11月18日の技術面接用。**本編6枚はNLPを学んだ経験が主役**。Webデモや公開用コードは補足資料。答えは暗記せず、実際に理解したことを自分の言葉で話すためのメモです。

## 最優先：何を学び、何が身についたか

### Q1. 今回、何を学習しましたか？
**回答例**：Pythonを使って自然言語処理の基礎を学びました。文章の前処理や単語の集計から始め、BoW・TF-IDFによる数値化、ナイーブベイズによる分類、正解データを使った評価まで一連の流れを学びました。特に、手法を使うだけでなく、比較条件をそろえて評価することの重要性を理解しました。

### Q2. なぜ自然言語処理を学ぼうと思ったのですか？
**回答例**：AIの中でも、普段利用する文章をコンピュータでどのように扱うのかに関心があったためです。機械学習モデルに文章をそのまま渡せないことから、前処理・数値化・分類という基本的な流れを実際に確かめたいと考えました。

### Q3. なぜ問い合わせ分類を題材にしたのですか？
**回答例**：請求や技術的な問題など、異なる内容の文章を分類する例は、数値化から評価までの流れを理解しやすく、問い合わせ振り分けという実務上の用途も想像しやすいからです。ただし、実際の企業の問い合わせ業務を改善した実績ではなく、学習用の題材です。

### Q4. 一番大きな学びは何でしたか？
**回答例**：正解率が高いことと、実際に信頼できるモデルであることは同じではないと学んだことです。今回は48件の架空データを1回分割して評価し、91.7%という結果でしたが、それだけでは実運用での性能を判断できません。正解率だけでなく、誤分類した文章やデータの偏りを確認する姿勢が身につきました。

### Q5. 工夫した点は何ですか？
**回答例**：BoWとTF-IDFを比較するとき、学習データの分割と分類器を同じにして、数値化方法だけを変更したことです。結果の違いが何に由来するか考えやすいよう、条件をそろえて比較しました。また、正解率だけでなく間違えた文章も確認しています。公開用コードの実装・整備は生成AIを活用したものです。

### Q6. 苦労した点は何ですか？
**回答例**：単にモデルが結果を出しただけでは、なぜそうなったのか判断しづらかったことです。そこで、BoWとTF-IDFの数値の意味や、学習とテストを分ける理由、誤分類の中身を確認しながら理解を深めました。原因をまだ特定できていないことは、未検証として区別しています。
※実際に体験していない苦労としては説明しないこと。

### Q7. この学習はWebエンジニアの仕事にどうつながりますか？
**回答例**：Webサービスでも、利用者の課題を理解して、適切な技術を選び、その結果を検証することが重要だと考えています。今回学んだ「処理の流れを理解する」「条件をそろえて検証する」「誤りから改善を考える」姿勢は、Web開発でも活かせると思います。将来的にはAIの知識を、実際に利用されるサービスの改善につなげたいです。

## NLPの内容：深掘りされた場合

### Q8. BoWとTF-IDFの違いは？
**回答例**：BoWは文章中の単語が何回登場するかを数値にします。TF-IDFはその出現回数に加えて、他の文章ではどれくらい一般的な単語なのかを考慮して重みを付けます。例えば「account refund」を数値化すると、BoWではaccountもrefundも1ですが、3文章で比較したTF-IDFではrefundの重みが大きくなります。ただし、珍しい単語が必ず分類に有効とは限りません。

### Q9. 多項ナイーブベイズとは？
**回答例**：カテゴリごとに、単語がどれくらい出現しやすいかという傾向を学習して分類するモデルです。文章をBoWやTF-IDFで数値化した後、その情報から請求と技術のどちらの可能性が高いかを比較します。単語の条件付き独立性を仮定するシンプルな分類器です。

### Q10. なぜ36件と12件に分けたのですか？
**回答例**：48件の75%を学習用、25%をテスト用にし、学習していない文章で予測性能を確認するためです。両カテゴリが24件ずつなので、層化分割により学習用は各18件、テスト用は各6件になります。この比率が唯一の正解ではなく、少量データなので今後は交差検証なども行いたいです。

### Q11. なぜBoWとTF-IDFの成績が同じなのですか？
**回答例**：今回の固定したテストデータでは、両モデルとも12件中11件に正解し、同じ1件を誤分類したためです。どの単語が結果に寄与しているかなど、成績が一致した原因まではまだ検証できていません。

### Q12. AccuracyとMacro F1の違いは？
**回答例**：Accuracyは全件のうち正解した割合です。F1はPrecisionとRecallの調和平均で、Macro F1はカテゴリ別に計算したF1を同じ重みで平均します。カテゴリの数に偏りがある場合に、Accuracyだけでは見落とす問題を確認できます。

### Q13. 誤分類の原因は何だと思いますか？
**回答例**：「The search feature returns an empty screen」という技術的な問い合わせを、請求と誤分類しました。学習データの少なさや語彙の不足が原因の可能性がありますが、原因は未特定です。単語が学習済みの語彙に含まれるか、各カテゴリでの単語の重みや確率を確かめたいです。語形が似ているからといった未検証の理由は断定しません。

### Q14. 日本語に対応させるには？
**回答例**：日本語は英語と違って単語が空白で区切られないため、MeCabなどを使った形態素解析や分かち書きを検討します。そのうえで日本語の正解ラベル付きデータを用意し、数値化と分類器を再学習・評価する必要があります。現状は英語のみです。

## 制作範囲・デモ：質問された場合

### Q15. 自分でやったこととAIに任せたことは？
**回答例**：自分自身はPythonやNLPの演習、学習テーマと要件の整理、AIへの指示、動作確認、評価結果の読み取りや改善方針の検討に取り組みました。GitHubに公開したソースコードの記述・修正、Webデモやテストの整備には生成AIを活用しました。公開ソースをすべて自力で書いたとは説明しません。

### Q16. Webデモはどのように動くのですか？
**回答例**：画面上で英文を選び、JavaScriptからPython標準のHTTPサーバーのPOST /api/predictにJSONで送信します。起動時に学習したBoWとTF-IDFのモデルが予測し、結果をJSONで返してブラウザに表示します。GET /api/reportで評価結果も表示します。Webデモは学習成果を確認するための補助です。

### Q17. AIが作成したコードはどう検証しましたか？
**回答例**：ローカルで起動して表示・分類結果を確認し、自動テストの実行結果も確認しました。以前の版ではpytest23件の成功を確認していますが、最新版でも全件成功したとは再確認なしに主張しません。自動テストだけで安全性や性能が保証されるわけではありません。
